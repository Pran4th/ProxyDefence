## The 4 GEM trackers that don't pass the missing-values check

Investigated, not fixed — the missingness is **structurally correct, not a data bug**.
GEM's own tracker schema encodes project lifecycle and facility type via mutually
exclusive fields:

- `ProposalYear` / `ConstructionYear` / `CancelledYear` / `ShelvedYear` / `StopYear` /
  `ActualStartYear` — a pipeline or terminal is only ever in **one** lifecycle state,
  so 5–6 of these 6 fields are legitimately null per row.
- `TotImportLNGTerminalCapacityinMtpa` vs `TotExportLNGTerminalCapacityinMtpa` — a
  terminal is import-only or export-only, never both.
- `Floating` / `Offshore` — sparse boolean flags GEM only sets when true.

Forcing these non-null would mean fabricating a construction date for a terminal
that was never built, or an export capacity for an import-only terminal — a worse
outcome than the current correct sparsity. The blanket 10% missing-value threshold
in `datasets/validation.py::check_missing_values` doesn't account for
mutually-exclusive field groups; that's a known limitation of the generic check, not
of this data.

## Sources blocked on API keys (not silently skipped — documented)

These are registered in `data_acquisition/source_registry.py` but have never been
fetched, because they require a signup/paid key not present in `.env`:

| Source | Requirement |
|---|---|
| EIA (petroleum/gas/coal/electricity) | Free signup key at eia.gov/opendata |
| FRED (proper `api.stlouisfed.org` endpoint) | Free signup key — worked around this session via the keyless `fredgraph.csv` public export instead |
| AIS vessel tracking | Commercial/paid (MarineTraffic, Spire, IHS) — the registered `url_template` is a placeholder, not a real endpoint |
| World Port Index (NGA MSI) | Free developer-portal signup key |
| UN Comtrade — legacy `comtrade.un.org/api` | Deprecated; this session used the still-working `comtradeapi.un.org/public/v1/preview` endpoint instead, which is keyless |

OPEC's `data_graphs/{id}.csv` endpoint was attempted this session for several
candidate dataset IDs — every request returns the generic OPEC website HTML (200 OK,
not CSV), meaning the real dataset IDs are only discoverable via inspecting their
site's JS-driven data calls. Skipped rather than reverse-engineered given time.

**If AIS or EIA data matters for the demo, the fastest unblock is providing those
API keys** — the connector plumbing (`connectors/rest_api.py` supports api_key/bearer/
basic/oauth2 auth) already exists, this is purely a missing-credential gap.
